# host-bridge: what was built

## A1 (server-platform #128)
- `event-contracts/src/host-bridge/`: `host-bridge.v2.ts` (envelopes, codes, `checkHostBridgeRequest`), `capabilities.ts` (methods, events, `HOST_BRIDGE_PARITY`), `fixtures.ts`.
- Fixtures: 37 router, 11 envelope, `parity.json`. Subpath export `@formulagen/event-contracts/host-bridge`.

## A2 (gamero, this branch)
- `commonMain/.../bridge/`: `BridgeProtocol.kt`, `BridgeCheck.kt` (same check order as the TS reference), `BridgeMethods.kt` (registry, strict serializers, `isSafeHttpsUrl`), `HostCapabilities.kt` (`Capability.Supported`/`Unsupported`), `BridgeRouter.kt`.
- `commonTest/.../bridge/HostBridgeFixtures.kt` is generated by `tools/sync-host-bridge-fixtures.py ../server-platform` (header names the source commit; `--check` detects drift).
- `BridgeRouterTest.kt`: all router fixtures, envelope shapes vs fixtures, parity listing, busy, failed (no detail leaks), cancel on context end, document change, events.

## A3 (gamero)
- `companion/NativeBridge.kt` is the JCEF transport. `classifyJcefQuery` sends v2 to `BridgeRouter` and leaves v1 on the old path. A v2 `watchContext` must be persistent: its first success is the context, and later successes carry events. Cancelling it ends the context.
- The bridge is attached on every desktop launch. The companion is a capability only when it is configured; v1 answers 403 without it.
- `HovelCompanion` throws `BridgeBusyException` when busy, and v1 still answers 400. `HovelCompanionCapability` adapts it.
- `bridge/DesktopHostCapabilities.kt`: links, haptics and lifecycle are `Unsupported` until phase C.
- Smoke page: a "Check host bridge v2" button. The expected lines are in `docs/hovel-native-validation.md`.

## Deviations from plan
- Unsupported is `Capability.Unsupported`, a sealed value, not a per-interface object.
- The router binds a context to `FrameFacts.documentId` as well as `contextId`; transports supply a document id that changes on navigation.
- The cloud container cannot build gamero (Google Maven blocked), so the bridge package was compiled and tested in a scratch Kotlin/JVM project pointing at these sources. Android and iOS compilation waits for the Mac run.

## Tech debt
- `HostBridgeFixtures.kt` drift check is manual until gamero has CI.
- `main.kt` changed only the `NativeBridge` construction. The jvmTest build compiles it.
