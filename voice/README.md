# :voice

On-device PocketTTS for the Ember pet. The Mac companion uses the JVM backend. iOS and Android are in this module so the same speak path can move onto the phone later. The app modules are not wired to it yet.

## What it does

`EmberVoice.speak` splits the line the same way the benchmark chunker does, caps each piece with `max(12, 4 + 0.8 * chars)`, and gives a piece of 24 characters or fewer at least 36 frames. A take longer than twice the expected audio is generated once more and the shorter one is kept. The listener events are `speech_start`, one `speech_level` per piece (RMS), and `speech_end`.

sherpa-onnx 2.0.0 finishes the language model for a piece before the first audio callback. This module does not pretend that callback is a frame streamed while the model is still generating. The first callback is still the TTFA the benchmark records.

Defaults, from the Linux VM confirmation: `numSteps` 1, temperature 0.3, seed 1, `firstPieceTargetChars` 40, `maxDurationRatio` 2, 2 threads. Tier names are local. A cached route is reused when the config version matches. A tier the host marks as below the floor goes to the server without a benchmark. Anything else speaks `task_finished` once and stays on device only if TTFA is at most 500 ms and RTF is at least 1.5.

## JVM

```bash
cd voice
./jvm-check.sh
./jvm-check.sh --speak
```

`--speak` needs the model from `spikes/ember-voice/mac/setup.sh`. It is not committed.

Android uses the same Kotlin sherpa API once `voice/libs/sherpa-onnx.aar` is present (not committed) and the build is `-Pgamero.mobileTargets=true`.

## iOS

`iosMain` calls `voice/ios/ember_voice_bridge.h`. The Swift and Objective-C++ next to that header include the sherpa-onnx 2.0.0 xcframework, so the Kotlin side does not guess sherpa's struct layout. `backend = "fluid-audio"` selects FluidAudio. Without that package linked, the bridge returns NULL and the engine says so.

One command, on the Mac that has the phones plugged in:

```bash
export SHERPA_ONNX_XCFRAMEWORK=/path/to/sherpa-onnx.xcframework
cd voice/ios-bench
./run.sh
```

It writes `bench-config.json`, then runs the corpus on every connected iPhone 14 Pro Max and iPad Pro. An iPad Pro that can install an iOS 18 build is an M-series iPad. Simulators are skipped. The JSON is in the test log and attached to the xcresult under `voice/ios-bench/results/`.

`./run.sh --self-check` only checks the device-name matching. It does not need Xcode.

The piece list is `voice/ios-bench/EmberVoiceBench/pieces.json`, generated by `./jvm-check.sh --write-pieces` from the shared splitter. Regenerate it when the splitter or the frame curve changes.
